# Где игра проверяет границу участка — и что нужно (и не нужно) для мода

## Коротко

**Blueprint-проект UE 5.5.4 не нужен и не поможет.** Точка, которую надо
изменить, лежит не в графе Blueprint, а в cooked-данных:

1. `AMTHouse.AreaSize` — сам прямоугольник участка (FVector, см). Меняется
   в памяти одним присваиванием, мод уже это делает.
2. `AMTHouse.MaxOutsidePlotDistance` — допуск «свисания» за границу.
3. `FMTBuildingRow::bAllowOutsidePlotArea` — флаг в таблице зданий: какой тип
   постройки в принципе разрешено ставить вне участка.

Ни одного узла Blueprint в этой цепочке нет: все три — сериализованные
свойства, которые читает нативная серверная логика.

## Почему Blueprint-проект не даст того, что ты хочешь

* **Классы нативные.** `MTHouse`, `MTBuilding`, `MTBuildingConstruction`,
  `MTHousingPlanningComponent` — это C++ (`/Script/MotorTown.*`), а не
  Blueprint. В usmap у них есть только свойства; графов для них не существует —
  их не «экспортируют» и не «пересобирают».
* **`ConstructionSystem*` — это плагин-маркетплейс**, а не логика участка.
  `ConstructionSystemBuildTool`, `ConstructionSystemComponent`,
  `ConstructionSystemSaveGame` и прочие отвечают за постановку объектов
  и сохранение постройки. К проверке «внутри ли участка» они отношения не имеют.
* **Cooking.** Даже если бы граф был, для UE 5.5.4 его нельзя пересобрать
  без редактора ровно этой версии и доступа к исходникам игры — а .pak
  собирается только с cooked-ассетами той же версии. Плюс мод обязан быть
  серверным: границу проверяет сервер.
* **FModel JSON** полезен ровно для одного: посмотреть значения свойств
  (например, `AreaSize` у конкретного дома). Для этого у меня уже есть
  собственный парсер и он работает на твоих файлах, без FModel.

## Что реально останавливает мод сейчас

Не отсутствие Blueprint, а **два файла, которых у меня нет**:

| Файл | Размер | Зачем |
|---|---|---|
| `Jeju_World.uexp` | 306 853 982 байта | значения `AreaSize` у 35 домов |
| `Building.uexp` (DataTable `/Game/DataAsset/Buildings`) | ~несколько МБ | строки с `bAllowOutsidePlotArea` |

Второй мне до сих пор не попадался: в `Jeju_World.umap` таблиц данных нет
вообще (0 экспортов класса `DataTable`), и в загруженных ассетах были только
`Houses` (участки) и `House` (актор). Именно в таблице зданий лежит флаг,
разрешающий ставить постройку вне участка — если для нужных типов он выключен,
то одного `AreaSize` может оказаться мало.

## Что от тебя нужно (по убыванию полезности)

1. **10-мегабайтный кусок вместо 293 МБ** — гибридный git-путь, см. ниже.
   Закрывает вопрос с `Jeju_World.uexp` целиком.
2. **`Jeju_World.uexp` целиком** через git (не через релизы).
3. **`Building.uasset` + `Building.uexp`** из `/Game/DataAsset/` — таблица
   зданий, чтобы проверить `bAllowOutsidePlotArea` по типам.
4. **JSON-экспорт из FModel** — только как справка, для проверки значений.
   Blueprint-граф он не заменяет, и мне он для патча не нужен.

## Гибридный путь: 10 МБ вместо 293 МБ

Релизы GitHub из моей песочницы недоступны (`release-assets.githubusercontent.com`
рвёт TLS), а git — работает. Компромисс: положить в git **разрежённый** файл —
только те куски, которые нужны.

В песочнице нет упаковщика pak, значит **собирать `.pak` буду не я, а ты** —
одной командой `repak pack`. Поэтому тебе нужен полный `.uexp` дома, а мне для
проверки достаточно фрагментов. 10 МБ уходят через git за минуту.

### Шаг 1 — нарезка (Windows, PowerShell)

```powershell
python tools\sparsify_uexp.py --uexp Jeju_World.uexp --out sparse.bin
```

Скрипт сам вырежет окно с домами (по умолчанию `242123897:4222`),
выровняет его по страницам 4 КБ и занулит всё остальное. На выходе
`sparse.bin` (~10 МБ) и `sparse.bin.meta` (размер, sha256 оригинала и
разрежённого файла, список окон).

### Шаг 2 — заливка в git

```powershell
powershell -ExecutionPolicy Bypass -File tools\push_uexp.ps1 -Source sparse.bin
```

### Шаг 3 — я собираю рецепт патча (`patch.json`, ~15 КБ)

```bash
python3 tools/unsparsify.py --sparse assets/sparse.bin --out work/Jeju_World.uexp
python3 tools/make_patch_recipe.py --window work/Jeju_World.uexp \
        --window-start 242123897 --umap Jeju_World.umap --usmap Mappings.usmap \
        --size 20000 --out patch.json
```

На каждый дом приходится 24 байта вектора `AreaSize` плюс 4 байта
`MaxOutsidePlotDistance` — итого 70 записей. В каждой записан и старый,
и новый байтовый образ, поэтому патч применим только к той версии игры,
с которой снят.

Проверил на синтетическом `.uexp` с реальными смещениями из `.umap`:
35 домов, 70 записей, применение даёт `AreaSize=(20000, 20000, 5000)`,
`MaxOutsidePlotDistance=20000`, размер файла не меняется, а подменённый
байт заставляет применитель отказаться от записи.

### Шаг 4 — применяешь рецепт и собираешь `.pak` (две команды)

```powershell
python tools\apply_patch_recipe.py --uexp Jeju_World.uexp --recipe patch.json
repak pack --version V11 BuildAnywhere_P.pak MotorTown\
```

Полная инструкция: `BUILD_PAK.md`.

## Если проще отдать 2 КБ

`tools/slice_uexp.py --uexp Jeju_World.uexp --out houses_slice.zip` даст окно
`242 123 897 … 242 128 055` — этого хватает, чтобы проверить декодер. Для
сборки `.pak` всё равно понадобится полный файл у тебя на диске.
